# 项目开发执行技能规范 & 钉钉通知报告标准格式

本技能为项目永久执行规范，所有开发、测试、提交、通知、文档更新操作必须严格遵守，统一项目开发流程与代码、交付标准。

## Agent 执行清单（每次任务）

任务开始：
1. 读取项目根目录 `.MemoryForAI/`，梳理历史与当前状态
2. 若目录不存在或为空，按 1.2 初始化

任务结束（有效代码/文档迭代后）：
1. 编写/运行单元测试（`tests/` 或既有 `__internal_tests/`）
2. 用户要求提交时，按 1.4 规范 commit
3. 每次有效 commit 后执行钉钉通知脚本（见下方命令）
4. 更新 `.MemoryForAI/` 与 README（如有变更）

## 1.1 目录规范（强制）

禁止污染项目主目录，所有文件严格按分类存放，统一目录约束：

- tests目录：存放所有测试文件、测试脚本、单元测试代码、测试配置等测试相关资源
- build目录：存放项目打包产物、编译文件、部署包等构建资源
- 其余业务代码、配置文件、静态资源、文档等，按项目通用规范归类至对应专属目录，禁止随意平铺放置

> 说明：本仓库历史单元测试位于 `__internal_tests/`，新增测试优先放入 `tests/`；文档在 `__docs/`。

## 1.2 项目记忆初始化规则

每次接收项目任务，优先执行项目环境读取操作：

1. 读取项目根目录下 .MemoryForAI 目录，用于追溯项目历史开发记录、逻辑、配置、迭代内容
2. 若该目录不存在/内容为空，判定为项目未正式启动，自动新建 .MemoryForAI目录，初始化项目记忆环境,关在git中排除该目录。
3. 每次任务完成后，必须更新该目录内容，留存本次开发、修改、测试、迭代记录，用于下次任务追溯

## 1.3 代码开发最低强制标准（零容忍违规）

所有代码开发必须遵守以下规范，杜绝不规范写法，保证代码可读性、可维护性、健壮性、可扩展性：

- 代码格式规范：禁止单行超长代码；代码结构分层清晰，禁止无结构平铺代码；杜绝重复冗余代码
- 命名规范：禁止使用拼音、无意义变量名（a/b/c、temp、tmp等无效命名）；变量、方法、类命名语义清晰、见名知意
- 常量与耦合规范：禁止硬编码常量，统一抽取全局常量配置；禁止紧耦合代码；严格拆分业务逻辑与IO读写逻辑，实现解耦
- 编码规范：禁止使用魔法数字，所有数字常量统一定义；禁止过度封装、禁止过度简化核心业务逻辑；禁止引入无必要的第三方依赖，精简项目依赖
- 健壮性规范：必须做参数校验、异常捕获与处理，禁止假设输入永远合法，杜绝参数异常、空指针等风险漏洞
- 接口规范：所有接口严格遵循 RESTful 设计规范
- 注释规范：所有注释统一使用中文；禁止省略必要注释，核心逻辑、工具方法、特殊处理逻辑必须添加说明注释
- 文件头规范：所有开发文件头部必须添加注释，注明 作者：孙文龙、文件用途、核心功能、创建时间

## 1.4 任务执行完整流程

所有项目任务必须按固定流程闭环执行，缺一不可：

1. 项目初始化：读取/新建 .MemoryForAI 记忆目录，梳理项目现有状态
2. 开发实现：按照上述代码规范完成业务开发、功能迭代、问题修复
3. 单元测试：编写对应单元测试用例，完成功能自测、边界测试、异常测试，确保功能正常、无bug
4. Git提交：测试通过后执行代码提交，提交信息严格分类规范：

   - feat：新增功能、新模块开发
   - fix：修复线上/测试bug、功能异常
   - refactor：代码重构、优化结构、解耦优化
   - doc：文档更新、注释补充、说明文案优化
   - 所有提交描述统一使用中文，内容清晰具体，不模糊笼统

5. 钉钉通知推送：每完成一次有效git commit提交，必须推送钉钉机器人通知，使用统一标准MD格式报告
6. 文档与记忆更新：更新 .MemoryForAI 项目记忆目录、项目README文档及相关配套文档，留存迭代记录

## 二、钉钉机器人通知标准报告格式

### 2.1 通知基础配置

- 机器人 token：`.env` 的 `DINGTALK_ACCESS_TOKEN`（勿写入业务代码）
- 请求方式：POST（必填，禁止GET请求）
- 通知关键字：通知
- 内容格式：固定 Markdown 格式，内容详实、结构化展示本次迭代信息

### 2.2 统一MD报告模板（强制使用）

每次git commit后替换对应占位内容，生成标准化通知内容，禁止随意修改结构

```markdown
### 项目开发迭代通知
#### 一、提交类型
【feat / fix / refactor / doc】（按需选择填写）

#### 二、本次迭代内容
1. 功能/修改说明：详细描述本次开发、修复、优化、文档更新的具体内容
2. 涉及模块：标注本次改动涉及的项目目录、文件、功能模块
3. 改动原因：说明迭代、修复、优化的初衷与需求背景

#### 三、测试结果
1. 单元测试：通过/未通过（说明测试用例覆盖情况）
2. 功能测试：核心功能正常运行，无异常、无报错
3. 边界/异常测试：验证通过，无潜在风险
4. 其他测试说明：补充特殊测试场景、兼容情况

#### 四、项目更新记录
1. 已更新.MemoryForAI项目记忆目录
2. 已同步更新README及相关配套文档
3. Git提交编号：【填写本次commit编号】

#### 五、开发人员
作者：孙文龙
```

### 2.3 通知内容要求

- 内容必须详细具体，禁止敷衍、笼统描述，清晰说明本次做了什么、改了什么、解决了什么问题
- 必须完整填写测试结果，真实反馈自测情况，体现交付质量
- 严格使用上述MD排版结构，保证每次通知格式统一、规整、可追溯
- 仅有效代码迭代、修复、文档更新commit需要推送，无实质改动的空提交无需通知

## 钉钉通知脚本用法

commit 完成后，从项目根目录执行：

```bash
python .cursor/skills/ifrit-project-dev/scripts/send_dingtalk_notify.py \
  --commit-type feat \
  --commit-hash <git短哈希> \
  --summary "功能/修改说明" \
  --modules "core/, config/" \
  --reason "改动原因" \
  --unit-test "通过，覆盖xxx" \
  --func-test "核心功能正常" \
  --edge-test "边界/异常验证通过" \
  --other-test "无"
```

或使用 `--report-file` 传入已填好的 Markdown 报告文件。

详细模板说明见 [dingtalk-template.md](dingtalk-template.md)。
